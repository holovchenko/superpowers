# PR #1831 controlled eval — design

**Date:** 2026-06-24
**Context:** PR https://github.com/obra/superpowers/pull/1831. Maintainer (obra) blocks
review until we show a controlled before/after: *"We can't review this until you do those
evals."* The two PR findings were NOT applied during the original cavekit A/B benchmark
(both arms ran stock tooling), so that run motivated the diffs but did not demonstrate them.
This eval supplies the missing before/after.

## Goal

Demonstrate, with stock-vs-patched A/B runs, whether each proposed skill change actually
changes agent output — and honestly report the result even if null.

## Findings under test

- **Finding 1 (`systematic-debugging`) — reshaped to amend-gate.** The PR currently ships a
  *soft adaptation* ("name the failure class, write the smallest regression test"). We
  reshape it to the literal mechanism that fired in the benchmark: when a fix verifies green
  but the suite is still red because of pre-existing failures **outside the locked edit
  surface**, the agent must autonomously (a) diagnose spec-vs-scope-vs-test, (b) prove
  no-regression via a differential (baseline fail-count / move-aside), (c) document the gate
  amendment, (d) re-scope the gate to "target test green + no NEW failures vs baseline", and
  proceed — instead of stopping to ask the human, touching out-of-scope files, or falsely
  declaring done.
- **Finding 2 (`writing-plans`) — `Invariants:` block.** Optional block in the Task
  Structure template binding each non-obvious invariant to a named test, with an
  "omit when none" escape hatch. Weaker / fuzzier; reported as secondary.

## Independent variable (exactly one block differs per arm)

- **F1:** stock `systematic-debugging` Phase 4 vs stock + the amend-gate step. Nothing else.
- **F2:** stock `writing-plans` Task Structure vs stock + `Invariants:` block. Nothing else.

Brief, fixture, model, tool access, and run index are identical across arms.

## Fixtures (deterministic, identical across arms)

- **F1 — red-baseline:** a small self-contained Node repo. One real bug in `src/<x>.js`
  with its own failing test (in-scope). Plus ~10 pre-existing failing tests in other files,
  unrelated to the bug. Brief: "fix the bug; edit surface is locked to `src/<x>.js`;
  gate = `npm test` green." The gate is deliberately unreachable in-scope, forcing the
  scope conflict identically on every run.
- **F2 — hidden-invariant:** a planning brief for a small feature whose correctness hinges
  on a non-obvious invariant (canonical: "dedup against ALL seen items, not just confirmed,
  or the loop never converges").

## Arms, runs, metrics

- **F1:** Arm A (stock) vs Arm B (amend-gate). **N=5** each. Run = `claude -p`,
  **Sonnet 4.6**, tools enabled (edit + bash), in a per-run sandbox copy of the fixture.
  Blind judge classifies each transcript into:
  `{autonomous-correct, asked-human, scope-violation, false-done, thrash/incomplete}`
  plus a binary `autonomous-correct y/n`. This directly measures the "0 rescues vs 1 rescue"
  claim. `autonomous-correct` = fixed the in-scope bug AND did not modify locked files AND
  did not stop for the human AND explicitly justified the remaining red as out-of-scope /
  proved no new regressions.
- **F2:** Arm A (stock) vs Arm B (+Invariants). **N=5** each. Run = generate an
  implementation plan. Blind judge scores 0/1/2: invariant surfaced (1) + bound to a named
  test (1).

## Bias controls

- Only the single skill block differs between arms; everything else is byte-identical.
- Judge receives transcripts with the arm label stripped, in randomized order.
- Run index is injected into the prompt so the 5 runs per arm are not cache-identical.
- Agent-under-test model fixed at Sonnet 4.6 (realistic default usage). Judge = Sonnet 4.6
  with a fixed rubric.

## Execution & artifacts

- All work in worktree `evals/pr-1831` of the memory-bus repo (same place cavekit artifacts
  live), under `evals/pr-1831/`.
- Heavy work (harness build, 20 agent runs, 20 judge runs) delegated to Sonnet subagents;
  Opus stays a thin orchestrator.
- Cost: ~20 headless Sonnet runs (≈150–500k tokens each per ponytail data) — real spend,
  user-accepted at N=5.
- Deliverable: `results/scorecard.md` (per-run table + before/after exemplar transcripts)
  plus raw transcripts. Posting to the public PR happens ONLY after user confirmation.

## Honest caveats (to state to obra)

- N=5 is a pattern, not statistics.
- F2 is the weaker finding (fuzzy metric); if the effect is null we say so plainly.
- If the amend-gate eval shows a real effect, we rewrite the Finding 1 diff in the PR to
  this mechanism (the PR currently has the softer version).
- If an arm shows no effect, that is a valid, reportable outcome — the eval is not rigged to
  confirm.

## Out of scope

- Re-running the full cavekit benchmark.
- Statistical significance testing (N too small; we report raw counts).
